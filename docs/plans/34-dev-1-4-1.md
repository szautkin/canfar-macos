## S — One session per assistant

### What happens today

- Every socket connection to the app gets a new session: `MCPBridgeService.session = UUID()`, "a relay
  reconnecting after Verbinal restarts is a new one".
- The relay (`Verbinal mcp`, `ResilientBridge`) reconnects by itself after Verbinal restarts and replays the
  client's `initialize`. The assistant believes it still has its session; every tool then answers
  `sessionRequired`, it calls `start_session` again, and the person sees the approval window again for an
  assistant they already allowed.
- Within one connection, `start_session` is already idempotent: `SessionApprovals.ask` answers an allowed
  session at once. The answer does not say it was already allowed, so an assistant cannot tell a first
  start from a repeated one.
- Approvals live in memory only: an app restart forgets them.

### What we want

1. An assistant calls `start_session` once. While its relay lives, a reconnection after Verbinal restarts
   keeps the same session: the same id, the same instructions, the same log. No new window.
2. A second `start_session` from an allowed session answers at once that it was already allowed: when, the
   instructions, and "do not call it again".
3. A session that was declined, or whose request was cancelled (the window closed, the assistant stopped
   waiting), is not allowed; the next `start_session` asks the person again, as now.

### Design

| Part | Job |
|---|---|
| **Relay identity** (`MCPCore`) | `ResilientBridge` makes one session id when the relay starts, and sends it with every connection to the app, in the replayed `initialize`'s `_meta` under `AgentSession.metaKey`. |
| **Bridge** (`MCPBridgeService`) | Takes the relay's id when it is a valid UUID; otherwise, as for direct connections and tests, a new one. One rule, in `AgentSession`. |
| **Approvals** (`SessionApprovals`) | Remembers the allowed sessions on disk (`Application Support/Verbinal/AgentSessions/approvals.json`). It reloads them at launch, and forgets one that has not been used for a set time, that the person ends, or when **Allow external AI agents** is turned off. Declined and cancelled requests are never remembered. |
| **Tool** (`StartSessionTool`) | Answers `alreadyStarted: true` with `allowedAt`, the instructions and a one-line note when the session was allowed before; `false` on a first start. |
| **Session log** | The same session's log continues; a reconnection writes one line, "reconnected after Verbinal restarted". |
| **The person's control** | **Settings ▸ AI Agent ▸ Session Logs** gains **End Session** on an open session: it forgets the approval, so the next call asks again. |

The words that tell assistants how to start (`AgentSession.instructions`, `describe_app`, AGENTS.md, the
tool's description) say once: call it once; a reconnection keeps your session.

### Tests first

- The relay sends the same id on two connections; the bridge takes it, and makes a new one without it.
- An approval survives a reload of `SessionApprovals`; one past its time, an ended one, and one after
  agents were turned off do not.
- A second `start_session` answers `alreadyStarted: true` with no window; after a decline or a cancel, it
  shows the window again.
- `SessionGateTests` and `MCPEraTests` still pass.

## F — Files of an observation, in Research

### What happens today

- The observation detail's **Files** tab lists every file of every plane. Its download button opens the
  file's address in the browser (`openURL`): nothing is downloaded by Verbinal, and Research does not know.
- A Research record holds one file (`localPath`). An assistant's `download_observation` with `file` fetches
  a chosen file (`DownloadService.downloadToTemp(publisherID:file:)`), and its record then points at that
  file instead of the one before.
- The person's **Download** asks where to save (`ResearchModel.download` → save panel); an assistant's goes
  straight to Downloads (`placeInDownloads`). Two paths for one job.

### What we want

1. The download button of a file in **Files** downloads that file, into Downloads, with Verbinal: no
   browser.
2. Research records it: the observation, kept or created, now has that file, among its others.
3. The file's button becomes a trash button: **Remove File…** deletes the file from this Mac (after asking)
   and removes it from the record. The button is a download button again.
4. Research's observation detail lists the observation's files, each with open, show in Finder and the
   trash button.

### Design

| Part | Job |
|---|---|
| **Data** | A table `observationFile` (a migration): the record, the file's URI, its local path and security-scoped bookmark, size, when it was downloaded, and who downloaded it. One row per file; a file's URI is unique within its record. |
| **Model** | `KeptFile`, and `DownloadedObservation.files`. Today's `localPath` stays the observation's main file for 1.4.1 (decision 2). |
| **One download path** | `ResearchFiles.download(file:of:)`: fetch (`DownloadService`), place in Downloads (`DownloadsFolder.move`, never over a file), and record. The **Files** tab, Research's detail and the assistant's `download_observation` `file` all call it. |
| **One removal path** | `ResearchFiles.remove(file:of:)`: delete the file, then its row; the kind "Remove files on this Mac" for an assistant (it waits by default). |
| **View** | The **Files** tab asks Research for each file's state: not kept (download), downloading (progress), kept (open, trash). The detail stays a view of the observation; it does not own downloads. |
| **Tools** | `download_observation` `file` records the file; `remove_downloaded_file` takes `file`; `get_downloaded_observation` lists the files. |

### Tests first

- Downloading a file creates the record when there is none, adds the file when there is, and never
  replaces another file of the record or a file in Downloads.
- Removing a file deletes it and its row, and leaves the observation and its notes.
- The migration keeps every existing record and note.
- The **Files** tab shows each state, and the assistant's path and the person's give the same record.

## V — Verbinal's files in VOSpace

### What happens today

Verbinal keeps files in the person's VOSpace, and each feature checks its own, or none:

| Folder | Written by | Checked |
|---|---|---|
| `.verbinal/manifests/<image>.json` | Image Discovery's probe jobs | Only for an image probed from this Mac, and only when the discovery sheet opens (`recoverFromVOSpaceIfPresent`). A manifest from another Mac, or from Verbinal for Windows or Linux, is never seen. |
| `.verbinal/exec/inbox`, `.verbinal/exec/out` | Remote Compute | After sign-in, by `RemoteComputeService.resumeWatching`, for the runs this Mac knows. |
| `.verbinal-scripts/` | Batch jobs launched with a `script` | Never. They pile up. |
| `Verbinal-Exports/` | **Upload to VOSpace** of an export | Never. |

### What we want

One place in the app lists what Verbinal keeps in VOSpace and how to check each. A background task checks
them after sign-in, and again from time to time, without ever slowing the app or deleting anything. What
it finds goes where it belongs: a manifest into Image Discovery's cache, a result to its run, old scripts
and exports to a list the person can clear.

### Design

| Part | Job |
|---|---|
| **`VOSpaceArtifactKind`** (protocol) | One kind of file: its id and title, its folder under the home, which files it means, how often to look, and `reconcile(_ listing:)`, which brings local state in line and says what it did. One conformer per kind, owned by its feature: `ProbeManifests` (Image Discovery), `ComputeResults` (Remote Compute), `StagedScripts` (batch jobs), `ExportBundles` (export). |
| **`VOSpaceArtifactCatalog`** | The one place that lists the kinds. Adding a kind is one conformer and one line. `docs/vospace-layout.md` says the same thing for people and for the Windows and Linux apps, which share the folders. |
| **`VOSpaceArtifactWatcher`** (actor) | Knows the catalogue, not the features. After sign-in, then at each kind's interval and on demand, it lists each folder once (one listing per folder, shared by its kinds), and hands the listing to the kind. It runs at background priority, one folder at a time, waits longer while VOSpace fails, and stops at sign-out. |
| **State** | Per kind: when it was last checked, what it found, and the last failure (`Application Support/Verbinal/StorageArtifacts/state.json`). |
| **Where the person sees it** | **Settings ▸ Storage** (a new section): each kind, its folder, how many files, when it was checked, **Check Now**; for scripts and exports, **Show in Storage**. A task on the activity bar while a check imports something. |
| **Tools** | `list_storage_artifacts` (read) and `check_storage_artifacts` (live); deleting stays with the existing storage tools, and their kinds of change. |

Existing checks join the watcher rather than run beside it: `resumeWatching` reads its results from the
`ComputeResults` kind's listing, and the discovery sheet's per-image recovery becomes the `ProbeManifests`
kind's reconcile for one image (DRY).

### Tests first

- A manifest in VOSpace that the cache does not have is imported; one the cache has, unchanged, is not
  read again.
- A late compute result is handed to its run once.
- Scripts and exports are counted, never deleted.
- The watcher: one listing per folder, back-off while VOSpace fails, nothing after sign-out, and the
  catalogue lists every kind (a guardrail test, as for the tools).

## Decisions for the person

1. **How long an allowed session lasts across restarts.** Recommended: while its relay keeps reconnecting,
   forgotten after 12 hours without a call, and at once with **End Session** or when agents are turned
   off.
2. **An observation's files.** Recommended for 1.4.1: today's main file stays as it is, and the new
   `files` list holds the files downloaded one by one; a later version can fold the main file into the
   list.
3. **Where a file goes.** The person asked for "just download". Recommended: every download goes straight to
   Downloads, never over another file, like an assistant's; the main **Download** stops asking where to
   save too, so the two paths become one. The alternative keeps the save panel for the main **Download**
   only.
4. **When the storage check runs.** Recommended: after sign-in, then every 30 minutes, and with
   **Check Now**; it imports manifests and results by itself and never deletes.
5. **A ledger in VOSpace** (`.verbinal/catalogue.json`, what Verbinal stored and where), for other Macs and
   the Windows and Linux apps. Recommended: not in 1.4.1; the shared `docs/vospace-layout.md` first.
