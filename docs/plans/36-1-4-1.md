# Plan 36 — Verbinal 1.4.1: the remaining work, smallest change first

**Date:** 2026-10-09 · **Branch:** `dev_1_4_1` (plan 34 done: `e277ef7f` … `10f3e3c9`) · **Release:** 1.4.1 (18)

One plan for all of 1.4.1's remaining work, from three sources:
1. **The opencode QA sweep** (`~/projects/splats/verbinal-mcp-qa-report.md`, against 1.4.0 at `531b2f9`).
2. **The review of `eumemic/exoplanets`**: can Verbinal carry that kind of flow?
3. **The person's priority:** results and all work in CANFAR storage, and the same state on every
   device.

## Rules

- **What goes in.** Bug fixes and the completion of what the app already sets out to do. No new
  features.
- **Resources.** Only what Verbinal already uses: CADC's archive (TAP with CAOM-2, DataLink, SODA, the
  target resolver), CANFAR storage (VOSpace), sessions, batch jobs, the image registry, and the CDS
  VizieR search it has.
- **Order: smallest change first.** Each item shows the files it touches, their size now, and roughly
  how many lines change. The order is by footprint, then by what depends on the code:
  1. no app code;
  2. one file;
  3. a few files;
  4. code not yet shipped (written for 1.4.1);
  5. code many places use;
  6. stored data that moves;
  7. pure moves, last.
- **The method.**
  - a failing test first;
  - one owner per rule;
  - areas that keep to themselves;
  - one green commit per item through the gates;
  - the manual, in both languages, and the parity matrix with each.
- **Not in 1.4.1** (listed at the end): new features, a light-curve view, footprint overlays, other
  archives.

## How to read an item

| Column | Meaning |
|---|---|
| **Kind** | **bug**: the app is wrong. **intent**: an existing feature does not finish what it is for. **content**: text in an existing feature. **test**: a guardrail, no app code. |
| **Touches** | Files, with their size today in lines. *New* is a file added; *unshipped* is code written on `dev_1_4_1`, not in 1.4.0. |
| **Δ** | Lines changed, about. |
| **Reach** | What depends on the code changed: callers, users, the tools' answers, stored data. |

## Principles for the sync and results (items 3.x–5.x)

1. **One sync engine, one rule.**
   - Each item is a file in `.verbinal/<collection>/`.
   - The newer change wins, and the one replaced is kept on the Mac where it lost.
   - Removals travel as marks, and a device marks only what it had.
   - Unknown fields are kept.
   - Nothing moves while `.verbinal/` is public.

   An area brings an adapter, never a second engine.
2. **One owner of where results go** (`ResultDestination`).
3. **Records in the database;** documents stay files.
4. **A file is known by what it is**, not by where it sits on one Mac.
5. **What is the device's stays the device's:** sign-ins and secrets, paths and bookmarks, the
   approvals given to assistants, session logs, pending proposals. A guardrail test checks each
   collection.
6. **Areas own their code:** model, services, views, tools, adapter, README. `AppState` grows no more.

## Can Verbinal carry an exoplanets-style flow?

**Yes**, with the person's code doing the science on CANFAR. Every stage has its tools today:
1. select with ADQL;
2. keep the selection;
3. fetch next to the compute;
4. process in batch jobs with replicas;
5. read the outputs;
6. triage in Research with tags;
7. check against the archive;
8. record how;
9. share through storage;
10. guide the assistant.

The gaps were items 2.11 (G1), 1.7 (G2), 2.10 (G3), 2.8 (G4) and 0.2 (G5), and the QA fixes on the
path: 2.6, 2.9, 2.7 and 1.4, 2.1, 1.2, 2.12.

## Decisions (the person said "go" to each recommendation, 2026-10-09)

1. **The relay looks for the live app when the sidecar is stale (2.4).** Recommended: yes. It looks
   only in Verbinal's own group container.
2. **Column ids (1.6).** Recommended: take the corrected spelling too, and keep the ids, so saved
   views keep working.
3. **One switch: Keep my work in VOSpace (3.2).** Recommended: yes; each collection is listed under it.
4. **Results default to storage first (4.1),** with a copy on the Mac when opened. Recommended: yes.
5. **Recent searches sync (3.5):** recommended, the last 100.
6. **Remember an assistant by name without asking?** Recommended: no. A client's name is its own word,
   and plan 34 S already keeps an allowed session across restarts.
